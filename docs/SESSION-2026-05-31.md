# Sesi Pekerjaan SCADA — 31 Mei 2026

## Ringkasan

Setup, perbaikan akurasi data weighing carousel CR3, dan tuning delay capture berat setelah sensor rising edge.

## Yang dikerjakan

### Infrastruktur
- PostgreSQL `scada_db` + user `scada_user` dibuat
- Aplikasi dijalankan via PM2 (`scada-app`, port **3001**)
- Admin default: `admin` / password dari env saat first boot

### Konfigurasi runtime (commit `4c3a116`)
- SQL: `100.127.239.116` / `SFM Main` / `WEIGHT_TABLE`, `PRESET_TABLE`
- OPC CR3: tag Siemens `PRODUCT_WEIGHT` + `PRODUCT_SENSOR`, scale **1**
- OPC CR1,2,4,5: Modbus sim, scale **0.01**

### Perbaikan akurasi data (commit `2940f25`)
- **Scale per tag OPC** dari `opcua.config.json` (bukan hardcode `/100`)
  - CR3 scale 1 → ~25 kg (sebelumnya 0.25 kg)
- **Delay capture** setelah sensor rising edge sebelum insert SQL
  - Nilai akhir: **700 ms** (`SENSOR_WEIGHT_CAPTURE_DELAY_MS`)
  - Counter di-freeze saat trigger; gross/nett dibaca setelah delay

### Tuning delay (sesi ini)
| Nilai | Catatan |
|-------|---------|
| 500 ms | Awal implementasi |
| 600 ms | Duplikat berat ~27.5%, hampir sama dengan 500 ms |
| **700 ms** | Aktif saat commit sesi ini |

## Hasil cross-check (data valid)

- Gross **~25 kg** setelah fix scale (cnt ≥ 274)
- STATUS 100% match toleransi gross (25.00–25.25)
- Dashboard History = mirror `WEIGHT_TABLE`
- Duplikat berat berurutan masih **~27%** — delay saja belum cukup
- Anomali: counter 732 & 736 pernah double-insert (sensor bounce)

## Saran lanjutan (belum diimplementasi)

1. Skip insert jika gross ≤ 0
2. Debounce sensor (cegah double trigger)
3. Pakai tag `GR03_NORMAL` untuk berat settled
4. Status dari NETT + toleransi nett (perlu alignment SOP)
